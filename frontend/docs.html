Authentication

All protected endpoints require Authorization: Bearer <JWT>. Access tokens expire in 30 minutes; the refresh token lives in an httpOnly cookie and rotates on every use.

POST/api/v1/auth/register

Create an account. Returns an access token and sets the refresh cookie.

POST/api/v1/auth/login

Email + password login.

POST/api/v1/auth/refresh

Rotates the refresh cookie, returns a new access token.

POST/api/v1/auth/logout

Revokes the current refresh token.

POST/api/v1/auth/oauth/github · /oauth/google

Exchanges an OAuth code for a session, same token shape as login.

Tasks

POST/api/v1/tasks

Creates a task and queues it to Celery — this is what the Workspace composer calls.

GET/api/v1/tasks

List/filter/paginate — powers History. Supports status, priority, language, search, page.

GET/api/v1/tasks/{id}

Single task detail.

PATCH / DELETE/api/v1/tasks/{id}

Partial update, or delete.

Agents & human approval

The pipeline runs Guardrail → Planner → Grounding → Human → Identity Broker → Coder → Tester → Security → Reviewer → Context Curator. Anywhere Human sits, the Workspace pauses.

GET/api/v1/agents/runs/{task_id}

Every agent run for a task — status, timing, step counts.

POST/api/v1/agents/{task_id}/approve

Approve the current plan.

POST/api/v1/agents/{task_id}/reject

Reject with an optional reason — triggers a re-plan.

POST/api/v1/agents/{task_id}/edit-plan

Submit an edited plan; auto-approved on submit.

POST/api/v1/agents/{task_id}/add-role

Add a new agent role mid-run — the C3 dynamic-assignment feature.

GET/api/v1/agents/{task_id}/risk-score

Guardrail's running session risk score and verdict.

GET/api/v1/agents/{task_id}/grounding-report

Grounding's pass/fail and any unsupported claims.

GET/api/v1/agents/{task_id}/identity-token

Scope + expiry + tool-call log — never raw secrets.

GET/api/v1/agents/{task_id}/curated-memory

Items this task promoted into long-term project memory.

Human-in-the-loop is not optional UIEvery approve/reject/edit/add-role call above pauses the LangGraph workflow at exactly that node until a response arrives — the frontend reflects backend state, it doesn't simulate agent progress on its own.

WebSocket

WS/ws/task/{task_id}

One connection per task, one Redis subscription per connection. Message shape: {type: "log"|"event", agent, level, icon, message, timestamp}.

The Workspace's activity feed and pipeline rail should key off type: "event" messages, not by parsing the human-readable log text.

Data isolation

Every query is scoped to the requesting userTasks, projects, outputs, and logs are all fetched through get_task(db, task_id, user_id=current_user.id) — a task ID that belongs to someone else 404s the same way a nonexistent one does, so the frontend can't accidentally leak another account's data even if an ID is guessed. Team resources follow the same pattern through get_team_with_membership: you only ever see teams and projects you're actually a member of. The frontend's only job is to always send the current user's bearer token — it should never accept or construct another user's ID for a request.
