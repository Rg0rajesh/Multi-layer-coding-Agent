How it works

One request, ten checkpoints.

Every task moves through the same pipeline — nothing skipped, nothing guessed at.

01

Screen & plan

Guardrail scores the request, Planner breaks it into subtasks.

02

Ground & approve

Grounding checks the plan against your repo, you approve or edit it.

03

Scope & build

Identity Broker issues a scoped token, Coder writes the implementation.

04

Verify & ship

Tester, Security, and Reviewer gate the output before it's yours.

The pipeline

Ten agents, each with one job.

No agent does more than one thing well — that's what makes the pipeline auditable.

Guardrail

Screens every incoming task and tracks risk across the session, not just per message.

Planner

Breaks a request into an ordered, file-scoped subtask list — max 8 per task.

Grounding

Checks the plan against real repo state before a human ever sees it. No LLM self-grading.

Human

A formal pipeline role — approve, edit, reject, or drop in a new agent mid-run.

Identity Broker

Issues a short-lived, scoped credential so Coder never runs under your full access.

Coder

Writes the implementation under the approved plan and the scoped token.

Tester

Writes tests and actually runs pytest against a scratch copy — not just a claim.

Security

Bandit + Semgrep scan before code ships — blocking, not a courtesy check.

Reviewer

Scores quality 0–10 and decides approved, approved-with-notes, or needs revision.

Context Curator

Tags what's worth keeping long-term — architecture decisions and known bugs only.
